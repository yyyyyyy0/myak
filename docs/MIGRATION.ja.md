# 0.1 / 0.2 から 0.3 への移行

[English](MIGRATION.md) | 日本語

0.3 では、スキーマ、インストール方法、フックの接続方法が変わります。自動で移行されるものはありません。

## 始める前に

- 古い pip/mise の editable インストールは削除してください。フックは非対話シェルの PATH からそれらを見つけられず、さらに新しいインストールを隠してしまいます。それぞれを管理している環境の中でアンインストールしてください（例: `pip uninstall myak`）。
- Syncthing を使っている場合は、マシンを 1 台選んでください。同期が終わるまで、他のマシンはアイドル状態（Claude Code を閉じた状態）にしておきます。

## 手順

1. 0.3 をインストールします: `./install.sh`（README を参照）。
2. スキーマの変更内容を確認します: `myak migrate --dry-run`。
3. マイグレーションします: `myak migrate`。整合性を確認し、`~/.claude/myak-state/backups/` にバックアップを書き出し（新しい 3 件を保持）、1 つのトランザクションでマイグレーションします。失敗した場合、DB は変更されません。
4. 手順 3 を実行するまで、フックは一度ログを残すだけで何もしません。これは意図した動作です。フックはマイグレーションを行いません。
5. 従来のフックを削除します: `myak migrate-settings --mode remove --dry-run` を実行し、続けて `--dry-run` なしで実行します。`.bak` が書き出されます。変更されるのは myak のエントリだけです。これを省くと、プラグインと従来のフックの両方が注入し、二重になります。
6. 古いノイズ行を整理します: `myak clean-legacy --dry-run` を実行して内容を確認し、その後 `myak clean-legacy` を実行します。対象は uuid を持たない行だけで、専用の `bak-clean-*` バックアップを書き出し（マイグレーションのバックアップとは別に整理されます）、影響を受けるベクトルを削除するので、`myak embed` が再計算します。`local-command-caveat` の行も削除されます。
7. Syncthing の同期が終わるのを待ってから、他のマシンを起動します。そこでも `myak migrate` を実行するのは、DB がマイグレーション済みの状態で届かなかった場合だけです。`myak migrate --dry-run` で確認できます。各マシンでは、インストールとプラグインの導入がそれぞれ必要です。
8. Claude Desktop: MCP コマンドは `~/.local/bin/myak-mcp` になりました（必要なら絶対パス）。`claude_desktop_config.json` を更新してください。

## 補足

- 0.3.x より前にベクトル検索を使っていた場合は、`myak embed` を一度実行してください。検索に必要な `models/*.ready` マーカーが書き出されます。後でモデルを切り替えるには `myak embed --model M --rebuild` が必要です。
- カーソル、バックアップ、ベクトルキャッシュはマシン固有です。`~/.claude/myak-state/` は同期しないでください。
- すべてのマシンに `.stignore` を追加してください（`.stignore.example`）。
- トランスクリプトがすでにない古いセッションは、変更されません。`cleanupPeriodDays`（デフォルトは 30）より古いトランスクリプトは、再インデックス化できません。
- コードより新しいスキーマは拒否されます。マイグレーション済みのマシンを使う前に、すべてのマシンをアップグレードしてください。


# スキーマ v2 から v3 への移行（エージェント source 列）

v3 では NULL 許容の列 `segments.source` を 1 つ追加し、各記憶を書き込んだエージェントを記録します。追加するのは列だけで、行は書き換えないため FTS インデックスには触れません。

1. 最初に、同期しているすべてのマシンで myak を更新してください。v3 より前のコードは v3 の DB に書き込めず、フックも意図的に何もしなくなるため、どのマシンかがマイグレーションする前に更新します。
2. マシンを 1 台選び、同期が終わるまで他のマシンはアイドル状態（Claude Code を閉じた状態）にしておきます。
3. そのマシンで `myak migrate --dry-run` を実行し、続けて `myak migrate` を実行します。整合性を確認し、`~/.claude/myak-state/backups/` に `bak-v2-*` バックアップを書き出し、1 つのトランザクションで列を追加して行数を検証します。
4. 他のマシンを起動する前に Syncthing の同期が終わるのを待ちます。DB が v3 で届いていれば、マイグレーションは不要です（`myak migrate --dry-run` で確認できます）。
5. マシンの DB が v3 になるまで、そのマシンのフックは一度ログを残すだけで何もせず、`myak save` / `myak_save` も書き込みを拒否します。これは意図した動作です。
